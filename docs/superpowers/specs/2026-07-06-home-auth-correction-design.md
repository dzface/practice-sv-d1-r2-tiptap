# 홈 게시글 목록과 인증 경로 수정 설계

## 목표

홈을 카테고리 링크 목록이 아닌 게시판별 최신글 화면으로 바꾸고, 데모에 남아 있는 인증 화면을 실제 서비스 경로로 옮긴다. 빅토끼와 빅토끼 인기글은 서로 다른 단계의 게시판으로 유지한다.

## 홈 화면

- D1의 모든 활성 게시판을 내비게이션 순서대로 표시한다.
- 각 게시판에는 최신 게시글을 최대 10개까지 표시한다.
- 게시글이 없는 게시판도 제목과 목록 영역을 숨기지 않는다.
- 각 목록은 10개 행에 해당하는 높이를 항상 확보해 게시판마다 크기가 달라지지 않게 한다.
- 데스크톱에서는 동일한 너비의 2열, 모바일에서는 1열로 배치한다.
- 빈 행에는 별도 안내 문구나 가짜 게시글을 표시하지 않는다.
- 게시글 제목은 해당 상세 페이지로 연결하고, 조회수와 추천수는 실제 집계값을 표시한다.

홈 서버 로더는 활성 게시판 목록과 게시판별 최신글 10개를 가져와 게시판 단위로 묶는다. 게시판마다 별도 요청을 반복하지 않고 한 번의 순위 조회로 게시판별 상위 10개를 가져온다. 게시글이 전혀 없어도 모든 활성 게시판과 빈 글 배열을 반환한다.

## 빅토끼 게시판과 인기글

- `빅토끼`(`/big`)와 `빅토끼 인기글`(`/trend`)을 모두 유지하며, 빅토끼 인기글의 데이터베이스 내부 ID도 `trend`로 통일한다.
- 릴토끼 글이 순추천 `추천 - 반대 >= 10`에 도달하면 빅토끼로 영구 이동하고 작성자에게 100포인트를 지급한다.
- 릴토끼 글이 순추천 `추천 - 반대 <= -10`에 도달하면 릴토끼 워스트로 영구 이동하고 작성자에게 30포인트를 차감한다.
- 빅토끼 글이 순추천 `추천 - 반대 >= 100`에 도달하면 빅토끼 인기글로 영구 이동하고 작성자에게 1,000포인트를 추가 지급한다.
- 릴토끼에서 빅토끼를 거쳐 빅토끼 인기글까지 이동한 글은 작성자에게 총 1,100포인트를 지급한다.
- 이동 규칙은 출발·도착 게시판, 순추천 방향과 기준, 포인트 증감을 별도 데이터로 관리한다.
- 게시글 이동 기록과 포인트 사건에 단계별 고유 키를 두어 각 이동과 포인트 반영이 한 번만 실행되게 한다.
- 투표 반영, 현재 게시판 변경, 이동 기록, 포인트 변경은 하나의 원자적 작업으로 처리한다.

## 인증 경로와 헤더

- 로그인 화면은 `src/routes/(auth)/login`에 두며 URL은 `/login`이다.
- 기존 `src/routes/demo/better-auth` 인증 화면과 서버 동작은 새 경로로 옮긴 뒤 삭제한다.
- 로그인 화면은 Google과 GitHub 로그인만 제공한다.
- 소셜 로그인이 완료되면 홈 `/`으로 이동한다.
- 이미 로그인한 사용자가 `/login`을 열면 홈으로 이동한다.
- 헤더는 비로그인 상태에 `로그인` 링크를, 로그인 상태에 POST 방식의 `로그아웃` 버튼을 표시한다.
- 로그아웃이 완료되면 홈으로 이동한다.
- 인증 실패 메시지는 각 폼 아래에 한국어로 표시한다.

## 데이터와 구성 요소

- `posts` 테이블은 게시판, 작성자, 작성 당시 이름, 제목, 본문, 조회수, 추천·반대 집계, 작성 시각과 상태를 저장한다.
- `category_movement_rules`는 출발·도착 게시판, 순추천 방향과 기준, 포인트 증감을 저장한다.
- `post_movements`는 게시글에 이미 적용된 단계별 이동을 기록한다.
- 게시판과 작성 시각을 기준으로 최신글 조회용 복합 인덱스를 둔다.
- 홈 전용 저장소 함수는 활성 게시판별 최신글을 최대 10개 반환한다.
- 홈 게시판 영역은 별도 Svelte 컴포넌트로 분리해 고정 10행 높이와 반응형 열 배치를 담당한다.
- `(app)` 레이아웃 서버 데이터에는 헤더 표시용 최소 사용자 정보만 포함한다.

## 오류 처리

- D1 연결이 없으면 기존과 같이 명확한 서버 오류를 발생시킨다.
- 존재하지 않거나 비활성화된 게시판의 글은 홈 조회 결과에서 제외한다.
- 삭제된 글과 공개되지 않은 글은 홈에 표시하지 않는다.
- 인증 오류는 서버에서 처리하며 비밀번호나 내부 오류 내용을 화면에 노출하지 않는다.

## 검증

- 홈 조회가 게시판별 최신순 최대 10개만 반환하는지 단위 테스트한다.
- 글이 없는 게시판도 빈 배열로 포함되는지 확인한다.
- 빅토끼 인기글의 내부 ID와 주소 슬러그가 모두 `trend`로 유지되는지 확인한다.
- 릴토끼의 순추천 `+10`, `-10`과 빅토끼의 순추천 `+100`에서 올바른 게시판 이동과 포인트 반영이 일어나는지 확인한다.
- 같은 이동 규칙이 다시 평가되어도 게시판 이동과 포인트 지급이 중복되지 않는지 확인한다.
- `/login`, Google·GitHub OAuth 시작과 로그아웃 요청을 확인한다.
- 로그인 상태에 따라 헤더 버튼이 바뀌는지 확인한다.
- 타입 검사, 린트, 단위 테스트, 프로덕션 빌드를 실행한다.
