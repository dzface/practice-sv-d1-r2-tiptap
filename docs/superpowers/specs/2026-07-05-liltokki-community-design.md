# 릴토끼 커뮤니티 설계

## 1. 목표

릴토끼는 기본 HTML에 가까운 단순한 화면을 가진 소규모 커뮤니티다. 모든 회원이 게시글과 댓글을 작성할 수 있고, 릴토끼 게시판의 글은 회원 투표 결과에 따라 빅토끼 또는 릴토끼 워스트 게시판으로 영구 이동한다. 빅토끼에서 다시 높은 순추천을 받은 글은 빅토끼 인기글로 영구 이동한다.

첫 출시는 커뮤니티, 인증, 포인트 장부, 최소 운영 도구에 집중한다. 쇼핑몰, 배송, 현금 환급, 사용자 간 포인트 양도는 제외한다.

## 2. 기술 구성

- SvelteKit 2와 Svelte 5
- Cloudflare Workers 어댑터
- Cloudflare D1과 Drizzle ORM
- Cloudflare R2 비공개 버킷
- Better Auth
- Tipex 게시글 편집기
- Zod는 폼, 업로드 등 외부 입력 검증에만 사용
- 별도 CSS 프레임워크 없이 일반 CSS 사용

Cloudflare 리소스는 다음 바인딩으로 연결한다.

- D1 `liltokki-db` → `DB`
- R2 `liltokki-files` → `FILES`

로컬 개발 데이터는 Wrangler의 로컬 저장소를 사용하고 실제 서비스 데이터와 분리한다.

### 포함

- 게시판 목록과 게시글 작성·조회·수정·삭제
- Tipex 본문과 R2 첨부파일
- 무한 단계 댓글과 대댓글
- 게시글·댓글 추천 및 반대
- 릴토끼 글의 빅토끼·워스트 영구 이동
- 조회수
- 포인트 적립·차감 장부와 회원 레벨
- 운영자(`admin`)·관리자(`manager`)용 최소 운영 도구
- 반응형 화면과 다크 모드 토글

## 4. 라우트와 화면

라우트 그룹은 URL에 나타나지 않는 `(app)`과 `(auth)`로 나눈다.

```text
src/routes/
├─ (app)/
│  ├─ +layout.svelte
│  ├─ +page.svelte
│  ├─ [category]/
│  │  ├─ +page.svelte
│  │  ├─ write/
│  │  └─ [postId]/
│  │     ├─ +page.svelte
│  │     └─ edit/
│  ├─ profile/
│  ├─ admin/
│  ├─ suspended/
│  ├─ policy/
│  ├─ privacy/
│  └─ terms/
└─ (auth)/
   ├─ +layout.svelte
   ├─ login/
   ├─ signup/
   └─ verify-email/
```

- `/`: 모든 활성 게시판을 내비게이션 순서대로 표시하고, 게시판마다 최신 글을 최대 10개까지 제목·조회수·추천수와 함께 표시한다. 빈 게시판도 숨기지 않으며 10개 행에 해당하는 너비와 높이를 유지한다. 데스크톱에서는 2열, 모바일에서는 1열로 배치한다.
- `/[category]`: 해당 카테고리(게시판)의 글 목록이다.
- `/[category]/write`: 게시글 작성 페이지다.
- `/[category]/[postId]`: 제목, 작성자, 본문, 첨부파일, 투표, 댓글 순으로 표시한다.
- `/[category]/[postId]/edit`: 게시글 작성자용 편집 페이지다.
- 댓글 작성과 편집은 상세 페이지에서 인라인으로 처리한다.
- `/profile`: 닉네임, 포인트 내역, 회원 탈퇴를 제공한다.
- `/admin`: 첫 출시에 필요한 최소 운영 기능만 제공한다.
- `/policy`: 게시글·댓글, 추천·반대, 포인트, 승격·워스트, 제재 및 신고에 관한 커뮤니티 운영정책을 안내한다.
- `/privacy`: 개인정보 수집·이용·삭제 정책을 안내한다.
- `/terms`: 서비스 이용약관을 안내한다.

## 5. 컴포넌트와 스타일

재사용 컴포넌트는 역할별로 분리한다.

```text
src/lib/components/
├─ layout/     Header, Nav, Footer
├─ ui/         Button 등 작은 공통 요소
├─ post/       PostList, PostItem, PostActions
├─ comment/    CommentTree, CommentItem, CommentEditor
└─ editor/     PostEditor
```

PicoCSS, Tailwind 등 전역 CSS 프레임워크를 사용하지 않는다. 의미 있는 HTML 요소를 우선하고 레이아웃은 `container → box → item` 구조로 통일한다. 공통 토큰과 기본 스타일은 작은 전역 CSS에 두고 세부 스타일은 Svelte 컴포넌트에 둔다.

다크 모드는 최초 방문 시 운영체제 설정을 따르고, 헤더 토글로 변경한 값을 브라우저에 저장한다. 초기 렌더링 전에 저장값을 적용해 색상 깜빡임을 방지한다.

## 6. 브랜드 설정과 카테고리 설정

사이트명, 회사명, 신고 이메일, 약관 시행일, 메타 설명, 로고·파비콘 경로는 타입이 적용되는 `site.config.ts`에서 관리한다. 비밀값은 Cloudflare 환경 변수에 둔다. 서비스 URL은 고정 JSON 값 대신 실제 요청 또는 환경 설정에서 얻는다.

화면에서는 익숙한 표현인 '게시판'을 사용할 수 있지만, 코드와 데이터 모델에서는 사용자의 선호에 맞춰 `category`로 통일한다. 카테고리 이름, 주소, 정렬 순서, 승격 기준처럼 운영 중 바뀔 수 있는 값은 D1 `categories` 테이블에 둔다. '읽을거리', '토끼굴' 같은 상위 메뉴 그룹은 카테고리와 구분되는 `group` 값으로 관리한다. 초기 내비게이션은 다음 그룹을 기준으로 시드한다.

- 빅토끼: 빅토끼, 빅토끼 인기글
- 릴토끼: 릴토끼, 릴토끼 워스트
- 핫딜
- 읽을거리: 과학, 유머, 공포, 역사, 사회, 기타
- 토끼굴: 주식·재테크, 코인, 익명, 고민상담, IT, 스포츠, 요리, 창작
- 운영관리: 공지사항, 건의하기

## 7. 인증과 가입

Better Auth가 사용자, 계정, 세션, 이메일 확인 정보를 관리한다.

로그인과 회원가입 화면은 데모 경로가 아닌 `(auth)` 라우트 그룹 바로 아래의 `/login`, `/signup`에서 제공한다. 헤더는 비로그인 상태에 `/login` 링크를 표시하고, 로그인 상태에는 어느 화면에서든 사용할 수 있는 로그아웃 버튼을 표시한다. 로그인·회원가입·로그아웃 성공 후에는 홈으로 이동한다.

### 이메일·비밀번호 가입

1. 이메일 아이디 입력
2. 허용 도메인을 목록에서 선택
3. 서버에서 허용 도메인 재검사
4. 6자리 인증번호 발송
5. 5분 안에 입력, 최대 3회 시도
6. 인증 성공 후에만 가입 완료
7. 가입 완료 시점부터 24시간 활동 제한 시작

허용 도메인은 다음 다섯 개다.

- `naver.com`
- `kakao.com`
- `gmail.com`
- `nate.com`
- `daum.net`

임시 이메일과 임의 도메인은 UI와 서버 양쪽에서 차단한다. 인증번호 재전송에는 대기시간을 둔다. 이메일 발송이 실패하면 가입을 완료하지 않는다. 로컬 환경에서는 실제 이메일 대신 시험 발송 방식을 사용한다.

### Google 로그인

Google 로그인을 첫 출시에 포함한다. Google이 확인한 계정에는 이메일 도메인 제한을 적용하지 않는다. 첫 로그인 뒤 사이트용 닉네임을 별도로 정한다. 동일 이메일의 계정 연결 정책은 Better Auth가 제공하는 안전한 흐름 안에서 처리한다.

## 8. 회원 권한과 상태

역할과 상태를 분리한다.

- 역할: `admin | manager | user`
- 상태: `active | suspended`

권한은 모든 변경 요청에서 서버가 검사한다.

- 비로그인: 공개 콘텐츠 읽기
- 유저: 가입 24시간 경과 후 글·댓글·추천·반대·업로드
- 관리자(`manager`): 모든 게시글·댓글 수정, 숨김, 복구, 삭제
- 운영자(`admin`): 관리자 권한과 회원 역할·정지 상태 변경
- 정지회원: 로그인 차단, 정지 사유와 해제 예정일 또는 영구 정지 안내

첫 `admin` 계정은 배포 과정에서 직접 지정한다. 화면에서 사용자가 스스로 역할을 올릴 수 없다. 관리 작업은 처리자, 시각, 사유를 감사 기록에 남긴다.

## 9. 데이터 모델

Better Auth 테이블과 커뮤니티 테이블을 분리한다.

### 주요 커뮤니티 테이블

- `profiles`: 닉네임, 역할, 상태, 가입 완료 시각, 포인트 잔액, 평생 획득 포인트
- `categories`: 이름, 주소 슬러그, 내비게이션 그룹과 순서
- `category_movement_rules`: 출발·도착 게시판, 순추천 방향과 기준, 포인트 증감
- `post_movements`: 게시글에 실제 적용된 이동 규칙과 처리 시각
- `posts`: 제목, 정화된 본문, 작성자, 작성 당시 닉네임, 현재·원래 게시판, 조회수, 이동·잠금·삭제 상태
- `post_attachments`: R2 객체 키, 원본 파일명, 형식, 크기
- `comments`: 게시글, 부모 댓글, 본문, 작성자, 작성 당시 닉네임, 삭제 상태
- `post_votes`: 게시글, 회원, 찬반
- `comment_votes`: 댓글, 회원, 찬반
- `point_transactions`: 회원, 증감액, 사유, 원인 대상, 생성 시각
- `moderation_logs`: 처리자, 대상, 조치, 사유, 처리 시각
- `level_thresholds`: 레벨과 평생 획득 포인트 기준

### 무결성 원칙

- 게시글·댓글 투표는 회원과 대상의 조합당 하나만 허용한다.
- 투표 변경은 기존 기록을 갱신하며 표시 점수는 기록에서 집계한다.
- 댓글 관계는 `parentId` 하나로 표현하고 자식 배열을 중복 저장하지 않는다.
- 게시글 이동, 잠금, 포인트 지급·차감은 하나의 원자적 작업으로 처리한다.
- 포인트 사건에는 고유 원인 키를 두어 같은 보상이 두 번 발생하지 않게 한다.
- 게시판 최신 글과 댓글 트리 조회용 복합 인덱스를 둔다.

## 10. 게시글 이동 규칙

자동 이동은 릴토끼와 빅토끼 게시판의 글에 적용한다. 다른 게시판은 추천 수와 관계없이 원래 게시판에 남는다. 모든 기준은 추천 수에서 반대 수를 뺀 순추천 점수다.

- 릴토끼 글이 순추천 `>= 10`에 도달하면 빅토끼로 이동
- 릴토끼 글이 순추천 `<= -10`에 도달하면 릴토끼 워스트로 이동
- 빅토끼 글이 순추천 `>= 100`에 도달하면 빅토끼 인기글로 이동
- 두 조건 중 먼저 도달한 결과만 적용
- 각 단계의 이동은 영구적이며 이후 점수가 바뀌어도 돌아오지 않음
- 게시글은 복제하지 않고 `categoryId`를 변경하며 `originalCategoryId`를 유지
- 댓글, 투표, 조회수, 기존 상세 주소의 대상은 같은 게시글을 계속 가리킴
- 이동 뒤 작성자는 수정·삭제할 수 없고 `manager` 이상만 조치 가능

빅토끼 이동은 작성자에게 `+100`, 워스트 이동은 `-30`, 빅토끼 인기글 이동은 `+1000` 포인트 사건을 만든다. 릴토끼에서 빅토끼를 거쳐 빅토끼 인기글까지 이동한 글의 작성자는 총 `+1100` 포인트를 얻는다. 단계별 포인트와 게시판 이동은 각각 한 번만 적용한다.

## 11. 댓글

댓글은 일반 여러 줄 텍스트만 허용한다. 게시글 상세 페이지 안에서 작성·편집하며 논리적으로 무한 중첩을 지원한다. 모바일에서는 일정 깊이 이후 들여쓰기를 더 늘리지 않고 연결선과 답글 대상 이름으로 관계를 표시한다.

작성자는 자신의 댓글을 수정·삭제할 수 있다. 자식 댓글이 있는 부모 댓글을 삭제하면 행과 트리는 유지하고 본문·작성자 표시를 제거한 뒤 `삭제된 댓글입니다`라고 표시한다.

## 12. 편집기와 파일

Tipex는 `PostEditor` 컴포넌트 안에 격리한다. 첫 출시 기능은 문단, 소제목, 굵게, 링크, 인용, 순서·일반 목록을 중심으로 제한한다.

저장되는 HTML은 서버에서 허용한 태그와 속성만 남긴다. 사용자가 원본 HTML을 직접 편집할 수 없게 한다. 외부 이미지 URL 삽입은 막고 필요한 파일은 R2를 통해 업로드한다.

R2 버킷은 공개하지 않는다. 서버가 로그인 상태, 소유권, 파일 크기와 MIME 형식을 확인한 뒤 임의 객체 키로 저장하고 전달한다. 목록의 대표 이미지는 첫 출시에서 만들지 않는다.

## 13. 포인트와 레벨

포인트는 변경 가능한 잔액만 두지 않고 모든 증감을 장부로 기록한다.

- 한국 시간 기준 매일 첫 로그인: `+5`
- 댓글 작성: `+1`
- 빅토끼 이동: `+100`
- 빅토끼 인기글 이동: `+1000`
- 릴토끼 워스트 이동: `-30`
- 잔액 최솟값: `0`

실제 차감액이 30보다 작더라도 원래 벌점 30과 실제 차감액을 함께 기록한다. 포인트 사용과 벌점은 평생 획득 포인트를 감소시키지 않는다.

| 레벨 | 평생 획득 포인트 |
| ---: | ---------------: |
|    1 |                0 |
|    2 |            4,000 |
|    3 |            8,000 |
|    4 |           16,000 |
|    5 |           32,000 |
|    6 |           64,000 |
|    7 |          128,000 |
|    8 |          256,000 |
|    9 |          512,000 |
|   10 |        1,024,000 |

첫 출시의 레벨은 닉네임 옆 장식이다. 정지회원은 누적 포인트와 무관하게 표시 레벨 0이며, 정지 해제 시 원래 레벨로 돌아간다. 기준은 운영 중 조정할 수 있도록 D1에 둔다.

첫 출시에서는 포인트를 적립만 하며 현금 환급, 양도, 외부 결제 수단으로 사용하지 않는다. 향후 운영자가 직접 판매하는 상품을 추가할 때 현재 잔액과 최소 구매 레벨을 함께 검사할 수 있도록 구조만 보존한다.

## 14. 회원 탈퇴와 개인정보

탈퇴 시 이메일, 비밀번호 해시, OAuth 연결, 세션, 프로필 등 계정 개인정보를 삭제한다. 게시글과 댓글은 유지하되 `authorId` 연결을 제거한다.

작성 당시 닉네임은 콘텐츠 표시용으로 유지한다. 단, 닉네임 자체가 개인정보이거나 별도 삭제 요청이 있으면 `탈퇴한 사용자`로 대체한다. 탈퇴 전에 게시물을 직접 삭제할 기회를 주고, 탈퇴 화면에서 게시물과 닉네임이 남을 수 있으며 잔여 포인트가 소멸함을 명확히 안내한다.

## 15. 최소 운영 도구

첫 출시의 `/admin`은 다음만 제공한다.

- 게시글·댓글 숨김과 복구
- 필요한 경우 영구 삭제
- 역할 및 기간·영구 정지 변경은 `admin`에게만 허용
- 조치 사유 입력과 감사 기록
- 승격·워스트 글 관리

일반 문제 콘텐츠는 복구 가능한 숨김을 기본으로 한다. 개인정보·권리침해 등 즉시 제거가 필요한 콘텐츠는 본문과 연결된 R2 파일을 영구 삭제할 수 있다. 본격적인 CMS는 실제 운영 요구가 생긴 뒤 별도 단계로 설계한다.

## 16. 오류 처리

기술 오류 대신 짧은 한국어 안내를 사용한다. 다음 상태를 구분한다.

- 잘못되거나 만료된 인증번호
- 인증번호 시도 횟수 초과와 재전송 대기
- 가입 후 24시간 활동 제한
- 정지 상태와 정지 기간
- 로그인·소유권·역할 부족
- 허용되지 않은 이메일 도메인
- 허용되지 않은 HTML 또는 파일 형식
- 업로드 및 이메일 발송 실패
- 이미 이동·보상 처리된 게시글

## 17. 검증 전략

핵심 규칙은 자동 테스트로 고정한다.

- 회원별 게시글·댓글 투표 중복 방지와 투표 변경
- 릴토끼 글이 `+기준` 또는 `-기준`에 먼저 도달했을 때 한 번만 이동
- 이동 이후 점수가 바뀌어도 복귀하지 않음
- 빅토끼·빅토끼 인기글 보상과 워스트 차감 중복 방지
- 일일 로그인 `+5` 중복 방지와 한국 날짜 경계
- 포인트 잔액이 0 아래로 내려가지 않음
- 평생 획득 포인트별 레벨 계산
- 가입 후 정확히 24시간 동안 글·댓글·투표·업로드 차단
- 역할, 정지, 소유자 권한 검사
- 탈퇴 뒤 콘텐츠와 닉네임 표시 유지, 계정 연결 제거
- 허용 이메일 도메인과 OTP 흐름
- HTML 정화와 파일 크기·형식 차단
- 부모 댓글 삭제 뒤 자식 트리 유지

라우트별 서버 테스트와 함께 주요 가입·로그인·글 작성·투표·이동 흐름을 브라우저 통합 테스트로 검증한다.
